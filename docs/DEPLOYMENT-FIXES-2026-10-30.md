## 主链路插件

- 卡片不再用 installed 状态给“已接入”绿勾；显示已安装、已注册、已加载、只读能力可用，以及缺配置/离线/不支持等原因。
- 配置注册读取 YAML id；DSH 加载证据来自实际 MCP 客户端 initialize/tools/list 的进程记录和当前插件状态签名。独立探针不会自动证明 DSH 已加载。
- MCP 服务监听插件状态变化并发送 tools/list_changed，支持同一进程安装/卸载/停用工具；旧版已运行进程需先重载一次，新版不用靠杀任意 Node 进程刷新。
- 插件健康检查分开报告已安装/已注册/已加载；表情库、群列表、空间读取使用两次只读检查，写操作不自动测试。API Key 缺失不会报可用；已配 Key 也不会自动触发付费语音/识图请求。
- catalog 增加能力依赖；已知 SnowLuma 2.x 空间接口不支持时标红，其他协议按声明和实际只读调用判断，不会因反复安装变绿。
- 首次部署无启用插件时加入 clock 只读示例，最终就绪要求 OneBot 登录、DSH Web、桥接、唯一注册、至少一个工具和 DSH 实际列出当前工具。

## 验证与边界

已运行完整 npm test（退出码 0）、36 项方法/兼容性测试、新增隔离集成测试、SnowLuma 专项测试、部署检查点测试、JS 语法和 git diff 检查；npm audit 当前 0 漏洞。修正测试脚本强制 process.exit 导致的 Windows libuv 退出断言，保留自然退出及失败退出码。

官方 v2.2.1 release API 当前能返回完整包与 SHA256；桥接固定标签提交已核对。没有在此机器自动登录 QQ、调用群管理写操作或付费接口，也没有声称已在 Windows Sandbox 从无 Node 完成全链路。bootstrap、登录启动项未在真实新系统执行；必须在目标电脑完成授权、扫码、白名单会话回复，以及 DSH 重启后的连接恢复验收。

桥接配置变化后的自动重启只适用于本版新启动的专用监督进程。用户自己启动的既有桥接不会被强制杀掉，需要在其控制台应用配置或自行重启。

源码修复包与发布状态分开：本地提交/压缩包不等于 GitHub 主分支或公网已更新，以实际推送及发布回执为准。
