# 主链路配置手册：SnowLuma + qq-bridge + DSH

> 这份文档只讲一条链路——**QQ → SnowLuma → qq-bridge → DSH → 本市场插件**。
> 它也是站内默认推荐的那条（插件市场首页「主链路直连」）。
> 文档写给自己人看：每一步做什么、怎么确认成功、失败了看哪里。
> **暂不挂进网站**，先当操作手册用。

---

## 0. 一分钟看懂整条链路

```
QQ 账号
  │  扫码登录（只有这一步必须你本人做）
  ▼
SnowLuma（协议端）         HTTP 3000 / WebSocket 3001
  │  把 QQ 变成 OneBot v11 接口
  ▼
qq-bridge（桥接，可选）    控制台 3100
  │  把人格、记忆、多角色接到 QQ 上
  ▼
DSH（DeepSeek Harness）    端口动态，脚本自动探测（本机实测出现过 11762）
  │  真正的大模型在这里，插件的宿主也在这里
  ▼
本市场 MCP 插件层          市场 3210 · 工具名 mcp__qqbot__*
```

端口对照表（照这个查，别记混）：

| 端口 | 是谁 | 说明 |
|---|---|---|
| 3000 | SnowLuma OneBot HTTP | 发消息、禁言、空间动态都走它 |
| 3001 | SnowLuma OneBot WebSocket | 可选；HTTP 模式够用 |
| 3100 | qq-bridge 控制台 | 打开能看见桥接状态 |
| 3210 | 本市场 | 你现在看的这个页面 |
| 3120 | 调音台 Voice Lab | 调音色、试听、写进 voice 插件 |
| 动态 | DSH | 不写死，脚本自动探测并记进 config.json |
| 8080 | 本地 Breeze-TTS | 可选语音后端，免 Key |

**一个必须理解的点**：这些插件不是你手动丢进 DSH 目录的文件，而是市场自己起一个 MCP 子进程，
由 DSH 启动时按 `cordis.patch.yml` 里的配置去连。所以**改了配置必须完整重启 DSH**，
点「刷新」或者热更新都不算。

## 1. 开始前，三件事必须先知道

**① 只用小号。**
SnowLuma 走的是个人号协议，不是官方机器人通道。腾讯风控会封号，这是协议本身的代价，
不是这个工具的问题。**不要拿主号试。**

**② Node.js 必须 20 或更高。**
插件沙箱用的 Node 权限模型从 20 起才有（20.x 叫 `--experimental-permission`，22 起叫 `--permission`，
项目会自动探一遍再用）。Node 18 及以下没有这套模型，装得上、跑不起来，只会报「插件全坏了」。
用 `node -v` 看，`v20.x` / `v22.x` 都行。

**③ 顺序不能反。**
先把 3000 打通、能查到 QQ 登录信息，再去接 DSH。反过来的话，DSH 里工具挂上了但一个都用不了，
排查时会误以为是插件坏了。

---

## 2. 第一步：Node.js

```bat
node -v
```

- 显示 `v20.x` 或更高 → 跳过这步。
- 显示 `v18.x` → 去 https://nodejs.org/zh-cn 装 20 LTS 或 22 LTS。
- 提示「不是内部或外部命令」→ 没装，或者装完没重开命令行窗口。

> 装完一定**新开一个**命令行窗口再敲 `node -v`。旧窗口读的是旧 PATH。

---

## 3. 第二步：SnowLuma 协议端

### 3.1 装

SnowLuma 没有自动安装器，官方发行包要手动下：

1. 打开 https://github.com/SnowLuma/SnowLuma ，下最新的发行包。
2. 解压到 **`C:\SnowLuma`**（市场默认就去这里找；放别处也行，之后在「连接设置」里改路径）。
3. 目录里应该能看到 `index.mjs` 或 `launcher.bat`。

### 3.2 启动并登录 QQ

1. 双击 `C:\SnowLuma\launcher.bat`（没有就 `node index.mjs`）。
2. 在它弹出的面板/窗口里**扫码登录 QQ**。
3. 登录成功后，确认 OneBot 服务开着：
   - HTTP 端口 **3000**
   - WebSocket 端口 **3001**（可选）

### 3.3 设 AccessToken（强烈建议）

在 SnowLuma 里给 OneBot 设一个 token，然后把同样的值填进本市场的
「连接设置」→ OneBot AccessToken。

为什么值得设：不设的话，本机上任何程序都能拿你的号发消息；
设了以后市场调用 3000 时带上 `Authorization: Bearer <token>`，协议端会校验。

> 市场里的密钥用 AES-256-GCM 加密存在本机，接口只回「配了没有」，不回明文。

### 3.4 确认成功（这一步别跳）

在命令行里执行，看能不能拿到 QQ 号和昵称：

```bat
node -e "fetch('http://127.0.0.1:3000/get_login_info',{method:'POST',headers:{'Content-Type':'application/json'},body:'{}'}).then(r=>r.text()).then(console.log)"
```

- 返回里有 `"user_id":你的QQ号` 和 `"nickname"` → **3000 通了，这一步成功**。
- 返回 `401` → token 没对上，把 SnowLuma 里的 token 抄到市场「连接设置」里。
- 连接被拒绝 → SnowLuma 没在跑，或者端口不是 3000。

## 4. 第三步：本市场

### 4.1 启动

```bat
cd /d <你放这个项目的目录>
node server.js
```

看到这三行就算起来了：

```
qqbot-plugins 插件市场已启动
地址: http://127.0.0.1:3210（未设口令，本机开放访问）
消息上报: POST http://127.0.0.1:3210/api/onebot/event
```

打开 http://127.0.0.1:3210 。

### 4.2 设个口令（如果这台机器不只你用）

在 `config.json` 里加 `"password": "你的口令"`，重启市场。之后打开页面要登录。

> 说实话：这个面板能装插件、能读写本机配置，**局域网里谁打开谁就能动**。
> 只在 127.0.0.1 用问题不大；要给别人看，先设口令。

### 4.3 部署整条链路

页面 →「部署方法」→ 最上面那张绿色卡「SnowLuma + qq-bridge + DeepSeek Harness」→
**部署整条链路**。它会按顺序真的跑：

```
node → snowluma → qqbridge → dsh
```

每一步都有实时日志。哪一步红了就停在那一步，不会继续往下装半成品。
失败时页面底部会出现「回滚这次部署」，把这次造出来的东西撤掉。

也可以到「链路组件」里一步一步点，效果一样，只是要按 1→5 的顺序。

---

## 5. 第四步：qq-bridge（可选但推荐）

qq-bridge 是中间层，负责把人格、记忆、多角色接上 QQ。**只装插件不装它也能用**，
只是机器人会显得"没有性格、记不住人"。

装法（它不归本市场管，要跑它自己的流程）：

1. 从 https://github.com/qqbot-hub/qq-bridge 拉下来。
2. 在它目录里 `npm install`，跑它自己的 setup，填 QQ 号和协议端地址（`127.0.0.1:3000` 或 `:3001`）。
3. 回到市场「链路组件」→ qq-bridge → 部署。脚本会找到它、起进程、验 3100。
4. 浏览器打开 http://127.0.0.1:3100 能看到桥接状态。

市场认的安装位置（按顺序找）：`config.json` 里的 `bridge.dir` → `C:\qq-bridge` → `runtimes/qqbridge`。
装在别处就改 `config.json` 的 `bridge.dir`。

---

## 6. 第五步：接进 DSH

### 6.1 一键写入

页面 →「接入 DSH」→ 填 profile 名（打开 `C:\Users\<你>\.dsh\profiles\` 看子目录名，
通常是 `desktop`）→ **一键接入 DSH**。

它做的事只有一件：往
`C:\Users\<你>\.dsh\profiles\<profile>\cordis.patch.yml`
里写一段被注释块包起来的配置：

```yaml
# === qqbot-plugins MCP BEGIN ===
- insert:
    - id: mcp-qqbot
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: qqbot
        transport: stdio
        command: '<node 的绝对路径>'
        args:
          - '<本项目>/mcp-server.mjs'
        toolCallTimeoutMs: 725000
# === qqbot-plugins MCP END ===
```

- 只动 BEGIN/END 之间，**不碰文件其他内容**；
- 写之前自动备份成 `cordis.patch.yml.<时间戳>.bak`；
- 可重复执行，重复执行不会写出两份。

### 6.2 完整重启 DSH

**不是关窗口，是彻底退出进程**（托盘图标也要退），再重新打开。
MCP 只在启动时加载。

### 6.3 验证

在 DSH 对话里搜 `mcp__qqbot__`，能看到一串工具（`qq_qzone_post`、`qq_tts`、`qq_group_ban`…）就是接上了。

## 7. 第六步：接入主链路专区那几张卡

页面 →「主链路直连」七张卡：

| 卡 | 插件 | 能力 | 要不要协议端 |
|---|---|---|---|
| QQ 空间动态 | `qzone` | 发说说 / 看好友动态 / 删自己的说说 | 要 |
| 语音与调音 | `voice` | 文字转语音发到群里；音色在调音台里调 | 要 |
| QQ 识图 | `vision` | 看图说内容、把图里的字逐行读出来 | 不要 |
| 发表情包 / 偷表情包 | `sticker` | 存群友的表情、按关键词发出去 | 要 |
| 识别视频 | `video` | 说清视频拍了什么（逐帧需要 DashScope） | 不要 |
| 群管理 | `group_admin` | 禁言 / 解禁 / 踢人 / 设管理 / 改名片 | 要 |
| 群信息 | `group_info` | 群成员、群资料、成员名片 | 要 |

「要不要协议端」这一列是实的：识图和认视频只调模型接口，SnowLuma 没起来也能用
（识图给图片链接或 base64 就行）；其余几项要真的往 QQ 里说话/取数据，协议端必须在线。

点 **一键接入主链路**，它走的是和「安装」同一条真实流水线（`recipes/plugin.mjs`），
不是改个状态位：

1. **查插件清单** — id 对不对、有几个工具
2. **校验插件文件** — 真的 import 一次，加载不了就不写状态（免得装个坏的）
3. **检查必填配置** — 插件如果把某项标成必填，缺了就停在这里让你填，不是装完一用才报错。
   现在这 50 个插件**都没有必填项**（接口 Key 属于「装完再填也行」，没填时调用会提示去配），
   所以这一步会写「没有必填项」；哪天有插件挂了必填，它才会拦住
4. **写安装状态** — `data/state/plugins.json`
5. **确认已注册进 DSH** — 没注册会自动补（"装了却用不了"多半是少了这步）
6. **自检** — 能列出工具才算真的可用

任意一步没过，会停在那一行并写清楚原因。

## 8. 识图 / 表情包 / 认视频怎么配

这三项跟前四项不一样：前四项是「让机器人在 QQ 里做事」，这三项是「让机器人看懂东西」。
看懂要靠多模态模型，所以都要填一个接口（表情包除外，它是纯本地）。

### 8.1 QQ 识图（`vision`）

在「主链路直连」的识图卡上点 **⚙ 配置**，三选一：

**① 硅基流动（最省事，国内直连）**

| 项 | 值 |
|---|---|
| 后端 | OpenAI 兼容接口 |
| 接口地址 | `https://api.siliconflow.cn/v1` |
| API Key | 硅基流动控制台里的 `sk-...` |
| 模型 | `Qwen/Qwen2.5-VL-72B-Instruct` |

**② 阿里云 DashScope（和认视频共用一把 Key）**

| 项 | 值 |
|---|---|
| 后端 | 阿里云 DashScope |
| 接口地址 | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| API Key | 百炼控制台的 Key |
| 模型 | `qwen-vl-max-latest` |

**③ 本机 Ollama（免 Key，图片不出本机）**

```bat
ollama pull qwen2.5vl:7b
ollama serve
```

后端选「本机 Ollama」，接口地址 `http://127.0.0.1:11434/v1`，Key 留空，模型 `qwen2.5vl:7b`。
7B 在消费级显卡/纯 CPU 上能跑，慢一些；只问「这是什么」够用，抠细节不如云端。

**两个工具的分工**

| 工具 | 什么时候用 | 返回 |
|---|---|---|
| `qq_see` | 群友问「这是什么」「图里几只猫」 | 一段描述 + 尺寸/体积 |
| `qq_ocr` | 截图、题目、报错、二维码下面的字 | 逐行原样文字，不翻译不总结 |

**图片怎么传进来**，三种写法都认：

1. 图片链接（`https://...`）—— 插件会先自己下载再转 base64。**为什么不等接口去抓**：QQ 的图片链接带 `rkey`，过期就 403，本机先拿下来最稳。
2. base64 或 `data:image/png;base64,...`
3. OneBot 的 `file` 值（`1A2B3C.image`）—— 会尝试 `get_image` 换回数据；换不到会明确告诉你「把链接传进来更稳」

**会拦住你的情况**

- 图片超过 **8MB** → 直接说超了，不静默截断
- 链接下回来不是图片（HTML 错误页、需要登录）→ 报「拿回来的不是图片」，不是把错误页丢给模型
- 没配 Key → 报「这条插件还没配置」，并告诉你去哪填、或者换 Ollama

### 8.2 表情包（`sticker`）

**为什么「偷」和「发」是一张卡、一个插件**：沙箱按插件隔离数据，拆成两个插件就会出现
「偷到的表情另一个插件看不见」。所以它们共用 `data/store/sticker/library.json` 一个库。

**偷（`qq_sticker_save`）** —— 四种来源任选：

| 你给的 | 插件做的事 |
|---|---|
| 带图消息的 `message_id` | 用 `get_msg` 翻出这条消息的图片段，再下载 |
| 图片链接 | 直接下载 |
| base64 / data URL | 直接用 |
| OneBot `file` 值 | 试 `get_image` 换数据 |

保存时会顺手记下**格式和尺寸**（`640×639`），并做去重：同一张图存两次会说「已经在库里了」。

**发（`qq_sticker_send`）**

- 按关键词：群友说「来个猫猫」→ 在名字和标签里模糊匹配，命中多个就随机挑一张
- 按 id：精确指定（`qq_sticker_list` 能查到 id）
- 什么都不给：随机一张

**库的硬上限**（超了会说清楚，不会悄悄丢）

| 限制 | 值 | 为什么 |
|---|---|---|
| 单张 | 512KB | 表情包通常几十 KB；这一档能挡住整段视频截图 |
| 全库 | 8MB / 60 张 | 沙箱里插件不能写独立文件，只能以 base64 存进 JSON，太大读写都会拖慢 |

满了就用 `qq_sticker_list` 看看，`qq_sticker_remove` 删几张。

### 8.3 认视频（`video`）

**两档后端，能力差很多，返回结果里会写明是哪种**：

| 后端 | 真的能看到什么 | 返回里怎么写 |
|---|---|---|
| 阿里云 DashScope `qwen-vl` | 整段视频逐帧看（按 fps 采样） | 「逐帧看（2 帧/秒）」 |
| 其他 OpenAI 兼容接口 | 只能看封面/首帧 | 「只看封面，不是逐帧」 |

**DashScope 配置**

| 项 | 值 |
|---|---|
| 后端 | 阿里云 DashScope |
| 接口地址 | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| API Key | 百炼控制台 → API-KEY |
| 模型 | `qwen-vl-max-latest`（或 `qwen-vl-plus`） |
| 抽帧密度 | 2（1–4；越大越细也越慢越贵） |

Key **可以先不填**把插件装上（「一键接入」不会被必填项拦住），但**用之前必须填**，否则每次调用都会回「这条插件还没配置」。

**两个工具**

- `qq_video_see` —— 说出视频讲了什么。**能不能逐帧看，取决于链接类型**：

| 你给的链接 | DashScope 后端 | 其他后端 |
|---|---|---|
| `mp4` / `mov` / `webm` 直链 | 逐帧看（按 fps 采样） | 只看得到封面 |
| 分享页，且页面自己声明了媒体直链 | 用页面里的直链，逐帧看 | 只看封面 |
| 分享页（B 站 / 抖音这类） | 拿不到播放地址，会明确说「这条是分享页，页面没给出可下载的播放地址」，并给出两个办法 | 用标题 + 封面回答，标注「只看封面」 |

- `qq_video_probe` —— 只读标题/简介/时长/封面/**有没有直链**，**不花模型额度**。想知道这条链接是啥、能不能逐帧，先跑这个：它写「直链：页面没给」就说明这条只能看封面。

**为什么 B 站/抖音的分享页逐帧看不了**：这些站点不把播放地址写进页面（`og:video` 指向的是 `player.html` 这种网页，不是一个视频文件），真实地址要带登录态和签名去换。
把网页地址丢给视频接口，接口只能看到一个 HTML 页面。这不是插件不支持，是站点的限制——想要逐帧就用 mp4 直链。

**为什么不用本机 ffmpeg 抽帧**：插件跑在沙箱里，默认没有起子进程的权限。
为一个抽帧功能给所有插件开口子不值得，所以逐帧这条路走云端视频接口。

**会拦住你的情况**

- 传的是本地路径 → 直接说「沙箱读不到本机文件」
- 视频太长、接口 140 秒没回 → 说「先试更短的片段」，而不是一直转圈
- 链接需要登录（私密视频、需要 Cookie 的页面）→ 抓不到封面，会说清楚并让你换 DashScope 或直接给封面图

## 9. 语音与调音怎么配

`voice` 插件有三种后端，在插件卡片的「⚙ 配置」里切：

**① OpenAI 兼容云端接口（要 Key）**

| 项 | 值 |
|---|---|
| 后端 | OpenAI 兼容云端接口 |
| 接口地址 | `https://api.siliconflow.cn/v1`（硅基流动）或 `https://api.openai.com/v1` |
| API Key | 对应平台的 Key |
| 模型 | 硅基流动填 `FunAudioLLM/CosyVoice2-0.5B`；OpenAI 填 `tts-1` |
| 音色 | 硅基流动形如 `FunAudioLLM/CosyVoice2-0.5B:anna` |

**② 本地 Breeze-TTS-2.cpp（免 Key，数据不出本机）**

```bat
breeze-server breeze-tts-2-q8_0.gguf --host 127.0.0.1 --port 8080
```

配置里：后端选「本地 Breeze-TTS-2.cpp」，接口地址填 `http://127.0.0.1:8080/v1`，Key 留空。
它支持用一句话描述语气（`instruction`，比如「轻声、带点笑意」）。

**③ SurfCore 语音引擎 voxd（免 Key）**

本地 8765 / 云端 8767。装了 SurfCore 就不用再配 Key，两边共用同一套音色。

**调音台**：市场里点「🎛 调音台」内嵌打开（本机 3120）。调好音色后一键写进 voice 插件，
不用手动抄参数。调音台没启动不影响语音——用默认音色也能发声。

## 10. 出错怎么办

按阶段分。每条都是：**看到什么 → 为什么 → 怎么处理**。

### 10.1 市场本身起不来

| 看到的现象 | 原因 | 处理 |
|---|---|---|
| `Error: listen EADDRINUSE :::3210` | 3210 被别的进程占了 | 改 `config.json` 的 `port`，或关掉占用的程序 |
| 打开页面一片空白 / 一直转圈 | `/api/list` 报错，多半是 `data/` 被改动 | 看命令行红字；`git status` 看 `data/catalog/*.json` 有没有被手工改坏 |
| `Cannot find module` | 少文件（用 zip 下了一半） | 重新 `git clone` 或重新解压 |
| 页面能开但数据全空 | 跑错目录了 | `server.js` 必须在项目根目录跑 |

### 10.2 协议端（SnowLuma）

| 看到的现象 | 原因 | 处理 |
|---|---|---|
| 市场报「这台机器上没找到 SnowLuma」 | 没装在 `C:\SnowLuma` | 挪到 `C:\SnowLuma`，或改 `config.json` 的 `snowluma.installDir` |
| 「启动了但 40 秒内没监听 3000」 | QQ 没登录 / 登录态失效 / 端口被改 | 看 SnowLuma 自己的窗口日志，先手动登录成功 |
| 3000 返回 `401` | token 不匹配 | 把 SnowLuma 里的 AccessToken 原样填进市场「连接设置」 |
| 端口探测通了，但调用报「Missing X-Self-ID」 | 端口上跑的是别的东西，或者协议端还没登录成功 | 市场用「openapi + OneBot v11 指纹」双路识别，两边都不认就说明不是它；先确认 QQ 登录 |
| 明明在跑，市场显示「协议端离线」 | 新版 SnowLuma 默认关掉 `openapi.json` | 不用管，指纹双路已经覆盖；仍显示离线就看 3000 的 `get_login_info` 是否返回数据 |
| 扫码一直失败 / 提示环境异常 | QQ 风控 | 换小号、换网络（手机热点试一次）、别在同一 IP 多开 |

### 10.3 qq-bridge

| 看到的现象 | 原因 | 处理 |
|---|---|---|
| 「没找到 qq-bridge」 | 装在别处 | 改 `config.json` 的 `bridge.dir` 指到它的根目录 |
| 「node_modules 不存在」 | 没装依赖 | 在 qq-bridge 目录里 `npm install`，再点一次部署 |
| 3100 打不开 | 进程没起来 / 端口被占 | 在 qq-bridge 目录里手动 `npm start` 看它报什么 |
| 桥接起来了但群里不回话 | 桥接指向的协议端地址不对 | 打开 3100 控制台，核对 OneBot 地址与 token |

### 10.4 接进 DSH 失败

| 看到的现象 | 原因 | 处理 |
|---|---|---|
| 「profile 目录不存在」 | profile 名写错，或 DSH 没启动过 | 打开 `C:\Users\<你>\.dsh\profiles\` 看真实子目录名，用它 |
| 「profiles 目录是空的」 | DSH 从没成功启动过 | 先手动开一次 DSH，让它生成 profile |
| 写进去了，但 DSH 里搜不到 `mcp__qqbot__` | 没完整重启 | 彻底退出 DSH 进程（含托盘）再打开 |
| 工具能看到，一调用就超时 | 子进程起不来 | 命令行手动跑 `node mcp-server.mjs`（它会停在等 stdin，这是正常的，看有没有红字）；常见是 Node 版本低于 20 |
| 重复点了几次「一键接入」，目录里一堆 `.bak` | 每次写入都备份（设计如此） | 正常，可以删旧的 `.bak` |

### 10.5 插件装了不生效

| 看到的现象 | 原因 | 处理 |
|---|---|---|
| 卡片显示「运行中」，DSH 里没工具 | 没重启 DSH | 完整重启 |
| 卡片显示「已停用」 | 停用了 | 点「启用」 |
| 安装时停在「检查必填配置」 | 少了必填项（如语音 Key） | 点「⚙ 配置」填完，再点一次接入 |
| 调用报 `ERR_ACCESS_DENIED` | 插件想写文件 / 起进程，被沙箱拦了 | 这是设计：插件只能在 `plugins/` 和 `scripts/lib/` 里读代码，写盘和起进程一律拒绝 |
| 插件读不到密钥 | 沙箱不下发 `secrets` 段 | 正常。要联网鉴权的插件，密钥由主进程代发请求，插件自己看不到 |

### 10.6 空间动态

| 看到的现象 | 原因 | 处理 |
|---|---|---|
| 「当前 OneBot 实现不支持空间接口」 | 只有 SnowLuma 提供空间扩展端点 | 换回 SnowLuma；NapCat / LLOneBot 没有这套接口 |
| 发出去但空间里看不到 | 风控 / 说说被折叠 | 换号试一次，确认不是内容问题 |
| 删说说报找不到 tid | tid 抄错，或已经删过 | 先 `qq_qzone_list` 看当前 tid |

### 10.7 语音

| 看到的现象 | 原因 | 处理 |
|---|---|---|
| 「还没配置语音接口」 | 后端和 Key 没填 | 「⚙ 配置」里选后端、填地址与 Key |
| 生成成功但发送失败 | 协议端不支持该音频格式 | 把 `format` 改成 `mp3`，或协议端开转码 |
| 本地 Breeze 连不上 | 服务没起 / 端口不是 8080 | 先跑 `breeze-server ... --port 8080`，再填 `http://127.0.0.1:8080/v1` |
| 云端 401 | Key 错或没额度 | 换 Key，或先用本地 Breeze 顶上 |

### 10.8 识图与认视频

| 看到的现象 | 原因 | 处理 |
|---|---|---|
| 「这条插件还没配置：需要 API Key」 | 没填 Key（识图还要确认没选成本机 Ollama） | 「⚙ 配置」里填 Key；识图也可以把后端换成 Ollama |
| 识图报「拿回来的不是图片」 | 链接 403、过期（`rkey` 超时）或返回了登录页 | 重新在群里发一次拿新链接；或直接把 base64 传进去 |
| 识图报「连不上 http://127.0.0.1:11434」 | Ollama 没起 | `ollama serve`，再看 `curl http://127.0.0.1:11434/v1/models` |
| 识图 404 / 模型不可用 | 模型名写错，或该平台没这个模型 | 硅基流动用 `Qwen/Qwen2.5-VL-72B-Instruct`；DashScope 用 `qwen-vl-max-latest` |
| 「图片 8MB，超过上限」 | 原图太大 | 换压缩图；或先发到群里让 QQ 压一遍再取链接 |
| 认视频只回「只看封面」 | 后端不是 DashScope | 换成 DashScope；别的接口普遍不支持视频输入 |
| 认视频 400，提示请求不对 | 该模型不支持 `video_url`，或它抓不到这个链接 | 换 `qwen-vl-max-latest`；私密/需要登录的链接它抓不到，先下载再传直链 |
| 认视频回「这条是分享页，页面没给出可下载的播放地址」 | B 站/抖音这类站点不把播放地址写进页面 | 弄到 mp4 直链再传；或者接受只用标题+封面（`qq_video_probe` 能先看有没有直链） |
| 认视频超时 | 视频太长 | 传更短的片段；或把抽帧密度降到 1 |

### 10.9 表情包

| 看到的现象 | 原因 | 处理 |
|---|---|---|
| 「表情库还是空的」 | 一张都没存 | 先偷：群友发表情时把 `message_id` 给它；或传图片链接 |
| 「这条消息里没有图片」 | 引用的消息是纯文字 | 换一条带图的消息 |
| 「超过单张 512KB 上限」 | 存的是大图/视频截图 | 表情包只适合几 KB～几十 KB 的图，换一张 |
| 「库满了」 | 到 60 张或 8MB | `qq_sticker_list` 看清单，`qq_sticker_remove` 删不用的 |
| 发了但群里没图 | 协议端不在线，或图片过大被 QQ 拒 | 看「运行监控」协议端是否在线；换小一点的图 |
| 同一个表情存两次 | 内容完全相同会被去重 | 正常行为，不是 bug |

### 10.10 群管理

| 看到的现象 | 原因 | 处理 |
|---|---|---|
| 「群 X 不在允许操作的群名单里」 | 开了群白名单 | 在插件配置里加上群号，或清空白名单 |
| 「管理员白名单已开启：需要 operator_id」 | 开了管理员白名单 | 让 AI 带上发起人的 QQ 号，或在配置里加人 |
| 禁言/踢人失败 | 机器人自己不是管理员 | 给机器人设管理员；这是 QQ 的权限，不是插件能绕的 |
| 危险操作要求 `confirm=true` | 配置里开了强制确认 | 按提示带确认参数，或关掉 `requireConfirm`（不建议） |

### 10.11 风控与封号

这类问题**没有技术解法**，只能降低概率：

- 只用小号；
- 别在同一 IP 上多开同一批号；
- 新号别一上来就频繁加群、发消息、@ 人；
- 被临时限制就先停几天，别换着号继续试。

## 11. 一份能照着敲的自检

按顺序跑，哪一步不对就停在那里处理。

```bat
:: 1. Node 版本（要 20+）
node -v

:: 2. 协议端活着吗（要能看到 user_id 和 nickname）
node -e "fetch('http://127.0.0.1:3000/get_login_info',{method:'POST',headers:{'Content-Type':'application/json'},body:'{}'}).then(r=>r.text()).then(console.log)"

:: 3. 市场自己体检（一次看全：DSH / SnowLuma / qq-bridge / 端口 / 插件）
cd /d <项目目录>
node scripts/doctor.mjs

:: 4. 插件能不能被加载（不联网，只验证代码）
node scripts/verify-plugins.mjs

:: 5. 市场起没起
node -e "fetch('http://127.0.0.1:3210/api/health').then(r=>r.json()).then(j=>console.log(j.ok,j.onebot&&j.onebot.impl))"
```

页面上的「运行监控」和它同源：**只报探测到的事实**。端口被别的程序占着时会直接说「不是它」，
不会因为端口亮着就报绿。

> 第 3 步的体检会自己去解市场里加密存的 AccessToken，所以只要你在网页「连接设置」里配过，
> 就不用再设环境变量。它报 401 才是真的 token 不对。

## 12. 什么情况别硬修

- **端口亮着不代表是它。** 3000 被别的程序占了，探测照样通。判断标准是能不能返回 QQ 登录信息。
- **DSH 端口会变。** 别在别处写死 11762 这类数字，每次都让脚本探测。
- **沙箱拦不住联网。** 现在的权限模型管文件、进程，不管网络。插件仍然可以往外发请求——
  所以装之前看清权限 chip（`访问网络` 那一条）。
- **跨框架插件装不进来。** AstrBot / Koishi / NoneBot / Yunzai 的原生插件只在各自框架里跑，
  本市场不做跨框架兼容，矩阵里写的就是"不支持"。
