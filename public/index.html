插件从哪来、能不能用

这里不玩虚的——来源和实测结果都摊开给你看。

目录
46 个插件、75 个工具的定义

名称、功能描述、工具名与参数，抓取自公开的 QQ 插件市场站点，并保留了各插件的上游出处（AstrBot / NoneBot / Koishi / Yunzai 社区同名插件），卡片上的「源自 xxx」就是那个链接。

实现
每个插件都是可运行的代码

原站的插件依赖它自己的加载器，抓不到实现。所以 46 个插件的能力都由本项目重新写成零依赖的 MCP 工具，跑在 Node 上，不装任何第三方包。

实测
59 项当场跑通，0 项报错

仓库自带 node scripts/verify-plugins.mjs，用真实参数把 75 个工具全跑一遍：59 项直接通过；15 项因为本机没开 QQ 显示「需在线」、1 项因为没填语音 Key 显示「需配置」——都是环境问题，不是插件坏了。免费画图接口偶尔限流，脚本会单独标成「需公网」而不是算失败。你可以自己跑一遍复核。

边界
哪些事它做不了

不抓版权音视频（点歌只给平台搜索链接）；群里禁言/踢人受机器人自身群权限限制；联网插件依赖公开免费接口，断网时会给出明确提示而不是假装成功。

🔌 接入 DSH（DeepSeek Harness）

与 qq-bridge 官方挂 mcp__snowluma__ 使用同一份配置文件、同一格式，互不冲突；不改动 qq-bridge 任何文件。

1
确认链路通SnowLuma（3000/3001）与 qq-bridge 已按教程跑通，DSH 里发一句话有回复。
2
一键写入点右侧按钮，把本市场写进 cordis.patch.yml（自动备份、可重复执行）。
3
完整重启 DSHpreset 与 MCP 只在启动时加载，务必完整退出再打开。
4
验证生效在 DSH 里搜 mcp__qqbot__，能看到工具即搭桥成功。
